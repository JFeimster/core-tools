# ToolForge Expansion Roadmap

This roadmap turns the ToolForge resource library into a practical expansion track for Core Tools.

## Near-Term Utility Goals

- Make the repo easier to operate in batches
- Keep the static directory more useful to builders
- Turn repeatable workflows into visible tools or playbooks where it helps users
- Keep repo-only guidance concise and platform-neutral
- Preserve static export, schema safety, and fast local validation

## Target User Workflows

- A builder starts on a branch, checks scope, validates, and opens a PR
- A founder turns an idea into a landing page plus a calculator or embed
- A funding broker builds a partner-safe tool and collection
- A content operator turns a topic into a page, brief, and lead magnet
- A maintainer keeps the repo clean and the knowledge snapshot current

## Data Model Considerations

- Keep visible entries schema-safe and concrete
- Prefer clear artifacts over generic "AI tool" language
- Keep CTA destinations useful and reviewable
- Use existing tags first; add taxonomy coverage only when it unlocks a real concept
- Keep repo-only docs for protocols, queues, and maintenance guidance

## What Should Become Visible Tools

Make it visible when the item is something a user would actually click in the directory:

- branch and batch workflows
- static site launch and QA helpers
- funding workflow builders
- SEO brief and lead magnet helpers
- knowledge sync and PR review helpers

## What Should Stay Repo-Only Docs

- branch rules and prompt protocols
- import queues and future idea lists
- schema notes and maintenance SOPs
- planning docs that do not help a directory user directly

## Next Build Sequence

1. Add the most useful platform packs
2. Turn the strongest packs into visible directory entries
3. Keep the import queue current
4. Review whether any new taxonomy coverage is actually needed
5. Refresh the project snapshot after each meaningful batch
6. Keep automation packs bounded and avoid introducing backend dependencies
6. Continue with the next platform pack after the operator workflow skills ship

## Success Criteria

- More useful directory entries
- Fewer one-off prompts
- Cleaner batch handoffs
- No loss of static-export safety
